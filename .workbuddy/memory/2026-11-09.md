

## 第二十八轮（12:00-12:50）连接手机：打包内置 adb/scrcpy + 连接向导

用户需求："如果我要打包成正式桌面应用的话，我要怎么连接我的手机呢"，并强调"注意不要影响原有功能的正常使用"。

### 发现的三处硬伤
- `tools/Moyu.spec` 只打了 `app.ico`/`app_icon.png`，adb/scrcpy 没进包；
- `mirror_app.py` 里 `base_dir()` 找不到 `scrcpy-win64-v5.0.1` 时**硬编码回落 `D:\moyu\tools`** → 换机器就打不开投屏；
- 配置写死在 exe 目录的 `config.json`（常没写权限），端口变了只能手动改文件；失败只有一句 MessageBox。

### 改动
- 新增纯函数（`tools/mirror_app.py`）：`app_dir()`、`resource_dir()`（`sys._MEIPASS`）、`find_scrcpy_dir(app, res)`（认 `scrcpy.exe`，候选 `<res>/scrcpy` → `<res>/scrcpy-win64-v5.0.1` → `<app>/scrcpy*`）、`config_path(app, res, frozen, appdata)`、`save_cfg(path, cfg)`、`parse_devices`、`is_ip_port`、`valid_pair_code`、`parse_pair_output`。
- 配置/日志目录：打包版 = `%APPDATA%\魔芋\`（`BASE` 即该目录，启动时 `os.makedirs`）；源码期仍是 `D:\moyu\tools`。打包版首次运行会把 exe 旁边的 `config.json` 当种子拷过去。
- `tools/Moyu.spec` datas 加 `('scrcpy-win64-v5.0.1/*', 'scrcpy')` → 包内 `_internal\scrcpy\`（16 文件 25MB，成品 exe 2.79MB，整目录 89 文件）。
- 新文件 `tools/connect_ui.py`：**纯 ctypes Win32 向导**（本机 Python 没有 tkinter，第一版用 tkinter 直接报 `No module named 'tkinter'`）。窗口类 `MoyuConnectWizard`，含设备列表 + 刷新/用这台设备 + IP:端口 + 配对码 + 配对/连接按钮 + 状态行；adb 调用在工作线程，`PostMessage` 回窗口。
- `mirror_app.py` 接线：`ID_CONNECT = 1003` 托盘菜单「连接手机…」；`start_scrcpy()` 开头 `if not devices: open_connect_wizard(); return`（不再弹错误框）；向导成功 → 写 `CFG['serial']` + `save_cfg` + 重启 scrcpy；`wizard: closed without connect` 时清 `state['wizard_open']`（否则菜单再也弹不出来——实测踩到）。
- **用户实测踩到的真缺陷**：`adb pair` 成功后拿**配对端口**去 `adb connect` → `10061 目标计算机积极拒绝`。手机无线调试有**两个端口**（配对端口 vs 主页「IP 地址和端口」）。修法：`pair_then_connect` 改三步——① 配对成功后看 `adb devices`（mDNS 常直接出现）② 否则 `adb mdns services` 里挑同 IP 的 `_adb-tls-connect._tcp` 端口再 connect ③ 仍不行则提示用户填「IP 地址和端口」点「连接」（UI 新增独立的「连接」按钮 + `connect_only`）。

### 教训
- `ctypes.wintypes` **没有** `WNDCLASSW`，要自己定义结构体；GDI/User32 的 64 位句柄必须写 argtypes，否则 `OverflowError: int too long to convert`。
- PowerShell 传中文参数给 python.exe 会变 GBK 乱码（`window not found: ħ��`）→ 用窗口**类名**定位，或写脚本文件。
- 截图被遮挡窗口用 `PrintWindow(hwnd, hdc, 2)`；但本机实测抓到的是桌面内容，最终用「SetWindowPos TOPMOST + ImageGrab」才拿到真像素。
