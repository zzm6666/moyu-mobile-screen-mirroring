## 新项目评估：手机投屏右下角小窗应用（讨论中，未编码）

- 需求：安卓手机投屏到 PC，右下角置顶小窗显示；场景为抖音/微信视频号/腾讯体育看球（边工作边瞄）。
- 技术路线倾向 **B：自写壳 + scrcpy 当渲染引擎**（不自研解码，看视频场景音画同步最稳）。iOS 全砍。
- 关键硬事实（已联网核实）：
  - scrcpy 4.x 原生支持 `--window-borderless --always-on-top --window-x/y/width/height`，右下角小窗零成本；音频转发需 **Android 11+**（12+ 开箱即用，11 需解锁屏放行，10 及以下无声）。
  - **DRM 黑屏风险**：Widevine L1 / FLAG_SECURE 让系统级录屏在受保护内容上黑屏（手机正常），与整屏/单应用采集无关。抖音(低风险) < 视频号(低中) < 腾讯体育看球(中高，版权内容)。密码/支付界面必黑屏属正常。软件无干净解法，只能硬件采集卡或改 PC 端看。
  - 鼠标反控走 scrcpy 零额外开发（左键拖拽=滑动，刷抖音换视频即此）；需自做「控制/穿透」模式切换防误触。
  - USB 稳定性远优于 WiFi（35-70ms vs 50-150ms 抖动），连续播放场景 USB 主力。
- 已锁定（2026-11-04）：**整屏投屏 + 鼠标反控**；手机 **Android 17**（音频转发无忧，无线调试可免线配对）；腾讯体育看**免费场次**（DRM 风险降一档，仍须实测）。
- 蓝牙不可行：BLE 5.x 应用层极限约 1.4Mbps，比 720p30 所需 2–4Mbps 低一个量级，且无 ADB over BT 标准实现、无视频 profile。有效传输仅 **USB / WiFi(TCP-IP)**；另有 Miracast（Wi-Fi Direct，仅显示不可反控）与 HDMI 采集卡（硬件绕 DRM）两条旁路。
- 计划：阶段 0 先实测三 App 黑屏（0.5 天，不编码）→ 再定投入。时间线约 1 周到日用。

- **三个关键坑（均已解决）**：
  1. `WNDCLASSW` 若是函数局部变量，返回后被回收 → 窗口过程指针悬空，`CreateWindowExW` 直接崩进程。必须用全局列表持有 WNDPROC 引用。

- 受限：COM（WScript.Shell 建 .lnk）与符号链接均被安全策略拦 → 桌面快捷方式需主人手动「右键 → 发送到 → 桌面快捷方式」。

### 四轮改动：自绘窗口（2026-11-04 主人要求操作栏/拖动/缩放/圆角）
- **关键结论**：scrcpy 的 SDL 窗口**不能被 SetParent 托管** —— 实测反复 SetParent，SDL 每次把父窗口重置回桌面（parent=None）。放弃嵌入方案。
- **改用「分层外框 + 透明洞」方案**：自绘 `WS_EX_LAYERED` 圆角窗口（PIL 生成 BGRA 外框图 + `UpdateLayeredWindow`），中间透明洞，scrcpy 画面作为独立窗口垫在洞后（`WS_EX_NOACTIVATE` 防抢焦点 + DWM 圆角）；视频区点击穿透到 scrcpy 保留反控。
- 功能：顶部毛玻璃操作栏（半透明白 + 标题「魔芋」+ 右侧 ×）、可拖动（`WM_NCHITTEST`→HTCAPTION）、可缩放（`WM_NCHITTEST`→HT* + `WM_GETMINMAXINFO`）、圆角、按手机宽高比 letterbox 不变形。
- 踩坑：Pillow 13 无 `Image.premultiply()` 方法 → 手动预乘纯色值；`UpdateLayeredWindow` 用 AC_SRC_ALPHA 需预乘 BGRA。
- 视频黑屏根因是**手机锁屏/熄屏**（`dismiss-keyguard` 后 dark ratio 1.00→0.00），非窗口问题。
- 验证：截图确认圆角、毛玻璃操作栏、标题、×、微信画面完整显示、无变形黑边。

### 五轮改动：修复操作栏不可见 + 定位边距 + 拖动缩放（2026-11-04）
- **操作栏「看不到」根因（两层）**：① 预乘/非预乘混用——背景用预乘 `FRAME_PREMUL`、文字用非预乘 `TEXT_COLOR`，PIL text() 混合后文字被冲淡成 (91,91,95) 而非 (55,55,60)，浅色毛玻璃上对比度极低几乎不可见。改法：**全非预乘绘制**（`FRAME_COLOR`/`TEXT_COLOR`/`CLOSE_HOVER_BG`）+ 统一 `premultiply()`（用 `ImageChops.multiply(channel, alpha)`，Pillow 13 无 `Image.premultiply`、本机无 numpy）后 `tobytes('BGRA')`。② **`UpdateLayeredWindow` 的 `psize=None` 在 WS_POPUP 下不渲染** —— 源区域大小不确定，毛玻璃整块消失只剩桌面；改回 `psize=SIZE(W,H)`（WS_POPUP 客户区=窗口区，不会重演 WS_OVERLAPPEDWINDOW 的收缩循环）。两个坑叠加排查了很久。
- **定位边距统一**：`move_to_bottom_right()` 改用 `SystemParametersInfoW(SPI_GETWORKAREA)` 取工作区（排除任务栏），右边距=底边距= `MARGIN=16`（原 24/72 不一致）。横竖屏一致。`ensure_frame_orientation()` 重写为**幂等重算**（`VIDEO_LONG=572` 固定长边、短边按 aspect 算，不再「交换宽高」——旧逻辑初始 orient=None 首次调用会误交换方向）。
- **拖动+缩放**：不能加 `WS_THICKFRAME`（会让 UpdateLayeredWindow 再次错位，毛玻璃消失）。改回纯 `WS_POPUP`；拖动走 `WM_NCHITTEST`→HTCAPTION+DefWindowProc（实测 +50,+40 精确跟随）；缩放**手动实现**（`start_resize/do_resize/end_resize`：WM_NCLBUTTONDOWN 边缘 SetCapture → WM_MOUSEMOVE 改尺寸 → WM_LBUTTONUP ReleaseCapture，最小 140×200，实测宽度 271→290）。
- 验证回执：右边距=底边距=16；标题最深色恢复 (55,55,60)；操作栏/×/圆角截图确认；frame_hittest 返回 2/11/15/10/1 正确。
- 遗留：手机 WiFi 下 `--stay-awake` 无效，熄屏后 scrcpy 视频流黑屏（手机侧，非代码问题；已 `settings put system screen_off_timeout 1800000` 缓解）。

### 七轮改动：只保留顶部操作栏 + 间隙消除（2026-11-04）
- **关键结论：scrcpy 嵌入（SetParent）不可行**。搜索确认正确嵌入法是「先改 WS_CHILD 样式（移除 WS_POPUP/CAPTION/THICKFRAME）再 SetParent」，实测 SetParent 确实成功且 1.5s 不被 SDL 重置，但 scrcpy 的 SDL 在**视频流到达渲染时会重新创建窗口**，导致 SDL_app 窗口消失 → 视频黑屏。结论：**视频无法真正嵌入窗口内，只能「外框+透明洞+独立 scrcpy 窗口」拼接**。DWM 原生窗口（Acrylic 毛玻璃）方案也放弃——Acrylic 下纯 GDI 文字不可见（需 alpha 绘制），且普通窗口无法做透明洞。
- **回滚到 layered 方案**，只修「间隙」：`FRAME` 从 6 改 **0**（视频洞直接贴边，child x 偏移=0，消除左右间隙）。但 FRAME 同时是缩放边缘 → 拆出独立 `RESIZE_EDGE=4`（frame_hittest 边缘判定用它，FRAME 只管内边距）。
- **外框只渲染顶部操作栏**：`build_frame_image` 的 mask 从「完整圆角外框+挖视频洞」改为「只画顶部一条圆角条 `rounded_rectangle([0,0,W-1,TOOLBAR_H-1], radius=6)`」，视频区全透明露出 scrcpy。操作栏圆角 radius 从 14 减到 **6**（平滑、弧度小）。
- 验证：child x 偏移 0（贴边无间隙）；操作栏 (165,167,169) 磨砂浅灰、标题+×可见；视频区直接铺满无边框。
- 未清理的遗留（无害）：`DwmExtendFrameIntoClientArea`/`msimg32.AlphaBlend`/`MARGINS`/`PAINTSTRUCT`/`BeginPaint`/`FillRect` 等 DWM 重构残留定义，已不再调用。
- 注：`GetStockObject` 在 **gdi32** 不在 user32（DWM 重构时踩过这个坑）。

## 第十一轮：拖动时操作栏与视频「脱节」
- 现象：拖动窗口时，视频区明显滞后于操作栏，像两块拼图错位。
- 根因（不是 bug 状态，是架构时序问题）：操作栏是 layered frame 窗口（`UpdateLayeredWindow` 自己画），视频区是 scrcpy 的独立顶层窗口，必须由我们 `position_scrcpy` 跟着挪。原 `update_frame` 先是 `build_frame_image`（实测 11.75ms）+ `premultiply/tobytes`（2.05ms）+ `draw_layered`，最后才挪视频窗口 → 每个 `WM_WINDOWPOSCHANGED` 要 ~15.8ms 才轮到视频跟上（毛玻璃背景失效时还会插入 `capture_blur`，单帧 112ms），拖动快时视频就落后 1~2 个事件。
- 修法（`mirror_app.py`）：
  1. `update_frame` 里把 `position_scrcpy` + `apply_child_round_region` 提到最前——先让视频到位，再慢慢画操作栏。
  2. 纯位移（`state['moving']` 且 `state['drawn_size'] == (W,H)`）直接 return，不重绘操作栏：分层窗口的内容与位置无关。
  3. 新增 `WM_MOVING(0x0216)` 分支：系统拖动循环里，lparam 指向「即将移到的矩形」，在 frame 被挪走**之前**就把视频窗口放到同一位置。
- 实测（`tools/.verify/dragsunc.py`）：拖动帧耗时 112.3ms（冷，含截屏模糊）→ **0.14ms**；缩放仍重绘 15.8ms（正确）；`render=0/10帧`、`pos=10/10帧`。


## 第十二轮：操作栏「毛玻璃没效果」+ 四边缩放「拖不动」（2026-11-04 17:0x-18:0x）
- 用户原话：「现在操作栏似乎并未实现半透明毛玻璃效果，还有鼠标拖拽窗口边缘以调整窗口大小的功能也并未实现，请检查」
- **毛玻璃根因**：`capture_blur()` 直接 `ImageGrab.grab(bbox=整窗)`，此时本窗口正可见 → 截到的是自己刚画的那条操作栏，模糊后必然一片均匀浅色（实测条带 RGB stddev 5.5/7.4/9.4，隐藏窗口后的真背景 40.0/43.0/46.2）。用户看到的是「一块实心灰板」，自然认为没实现。
  - 修法：新增 `blank_layered(hwnd, W, H)`（`draw_layered(hwnd, W, H, bytes(W*H*4))` 刷全透明）+ `DwmFlush()` + `time.sleep(0.012)`（等合成器真正吐出透明帧，否则偶尔截到上一帧自己，条带 stddev=0），只截 `(r.left, r.top, r.right, r.top+TOOLBAR_H)` 那一条。
  - 接地真值脚本 `.verify/gt.py`（藏窗后截同条带）验证：app 日志 `blur: strip stddev=13.9~34.6` 与地面真值同量级 → 现在截的是真背景。
  - **视觉验收三段调参**：`BLUR_RADIUS` 34→12（太糊会把背景糊成灰），`TINT_TOP/BOTTOM` 白玻璃 (255,255,255,120)/(238,243,251,96)，新增**按背景亮度自适应**的深色玻璃 `TINT_TOP_DARK=(22,24,30,88)`/`TINT_BOTTOM_DARK=(12,14,20,64)`（`state['bar_dark'] = lum < 128`，与 Windows 亚克力逻辑一致；白玻璃压暗底必然糊成灰），文字/×/高光随主题切换（`TEXT_COLOR_DARK`/`CLOSE_X_COLOR_DARK`/`CLOSE_X_HOVER_DARK`），`SATURATION` 1.35→1.6。
  - **新增颗粒感 `GRAIN=6`**：`Image.effect_noise((W, th), GRAIN)` + `ImageChops.add(rgb, noise, 1.0, -128)` 做有符号叠加（PIL 没有负值模式，add 的 offset 参数是唯一干净写法）。这是让纯色背景也「读得出是磨砂材质」的关键——亚克力之所以像玻璃，靠的就是细噪点。
  - 离线验收 `.verify/glassfinal.py`：用彩色渐变背景渲染白玻璃/深色玻璃两组，色块确实透出来且带颗粒（`glass_final.png`）。
- **四边缩放根因（两条）**：
  1. `frame_hittest()` 里 `if cy < TOOLBAR_H: return 1/2` 排在边缘判断之前 → 操作栏内的上/左/右边缘永远只能拖动。
  2. 竖屏时视频子窗口 `vx=0, vw=W` 完全盖住 frame 的左/右/底边 → frame 根本收不到那些点的 `WM_NCHITTEST`。
  - 修法：边缘判断提到工具栏分支之前；四边/四角全部改由已安装的 `WH_MOUSE_LL` 钩子 `mouse_hook_proc` 判定——新增纯函数 `rect_edge_hit(r, x, y, grab=EDGE_GRAB=6)`、`_inside_frame()`、`_owns_point()`（`WindowFromPoint` 命中 frame/child 或前台是它们），按下即 `start_resize(f, hit)` 并吞掉事件，悬停按 `CURSOR_FOR_HIT` 换 `IDC_SIZEWE/SIZENS/SIZENWSE/SIZENES`。
  - **关键教训**：`SetCapture` 救不了——鼠标压在 scrcpy 子窗口上时 frame 收不到 `WM_MOUSEMOVE`（实测 `do_resize` 一次都没被调）；改为 `SetTimer(frame, TIMER_RESIZE=3, 10)` 每 10ms 轮询 `GetCursorPos` 驱动 `do_resize`，抬键由钩子收尾。另一个坑：钩子吞掉按下事件后 `GetAsyncKeyState` 永远读不到按下，不能拿它做松手兜底。
  - `do_resize` 增加工作区夹取：被拖边为锚点，`max_w/max_h` 由锚点算，横向 hit 用 `w_cap = min(max_w, int((max_h - TOOLBAR_H - FRAME) * aspect) + 2*FRAME)`，纵向用 `h_cap`，超出就缩回来——窗口永远不会被拖到屏幕外（右/下已贴边时只能往里缩，符合直觉）。
