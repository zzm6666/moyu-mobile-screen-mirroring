## 第十九轮：拖动时视频区抖动/右侧底部黑边（根因：我们自己两处尺寸不一致）

- 现象：拖动窗口时视频画面抖动，右/下出现黑边。
- 误判过程：先怀疑 scrcpy 锁定窗口长宽比（dragedge 探针看到 child 尺寸在 264x576 与 260x572 之间跳），于是加了 
  `--no-window-aspect-ratio-lock` 与 `--render-fit=stretched`；加完仍 7/30 步异常。
- 真因：`frame_proc` 的 WM_MOVING(0x0216) 快路径用 `calc_video_rect()` 的**裸尺寸**摆视频窗口，
  而 `position_scrcpy()` 用 `child_box()`（含 OVERSCAN=2）。拖动时两条路径交替执行 →
  视频窗口每帧在 264x576@(-2,36) 与 260x572@(0,38) 之间跳 4px → 画面抖；跳成小尺寸时
  scrcpy 右/下那 1~2px 黑底露进可见区 → 黑边。
- 修法：WM_MOVING 快路径改用 `child_box(...)` 同一套尺寸；新增 `TestDragPath` 守住这条路径。
- 验证（打包版）：`dragedge.py` 30 步 0 异常、offset 恒 (-2,36)、size 恒 (264,576) → VERDICT CLEAN；
  逐边像素：row38 = 纯白接缝线，bottom 605~609 = 201/241/240/239/239 全是画面，无黑边。
- 测试 63 例通过；成品 `D:\moyu\tools\魔芋\魔芋.exe` 2,766,199 B / 65 文件。

## 第十九轮：整窗阴影

用户需求：给整个窗口（操作栏+视频区域）加淡淡阴影；随时可回退。

- 难点：窗口是 UpdateLayeredWindow 分层窗口，系统不会给它画阴影（没有非客户区）。
- 方案：窗口四周外扩 `SHADOW_PAD=10`，在这圈里自己画模糊的黑色圆角矩形；圈内对鼠标返回
  `HTTRANSPARENT`(-1)，避免吃掉桌面点击。否决「再开一个阴影窗口」——多一个要同步的窗口，
  会重演之前的脱节/闪烁问题。
- 常量：`SHADOW_PAD=10`、`SHADOW_BLUR=4.0`、`SHADOW_ALPHA=120`；回退只需 `SHADOW_PAD=0`。
- 新增纯函数：`content_size` / `content_rect` / `win_rect` / `add_shadow`，坐标换算全部走它们，
  不再散落硬编码。
- 接线：`update_frame`（画布外扩 + `add_shadow`）、`position_scrcpy`、`WM_MOVING`、
  `frame_hittest`（操作栏/关闭按钮/抓边都 +pad，圈带返回 HTTRANSPARENT）、`_inside_frame`
  （用内容矩形，`edge_hit` 的 toolbar 传 `TOOLBAR_H+SHADOW_PAD`）、`start_resize`（存内容矩形）、
  `do_resize`（`win_rect` 落地，`max_w/max_h` 减 pad）、`WM_GETMINMAXINFO`、`ensure_frame_orientation`、
  `main()` 建窗尺寸。
- 测试：`TestShadowPad` 3 例 + `TestAddShadow` 5 例，全库 73 例通过。
- 实测：280x630 窗口（内容 260x610）；白底上阴影把 255 压到 200，8~10px 内衰减到 255；
  视频子窗口偏移恒 `(8,46)=(PAD-OVERSCAN, PAD+TOOLBAR_H-OVERSCAN)`；拖左边缘 −40px →
  窗口 320x718、内容同步、子窗口偏移不变（`VERDICT OK`）。
- 坑：注入式测试前必须重新 `GetWindowRect`，用户同时在动窗口会让注入点打空（第一轮误判「没缩放」）；
  `ctypes.wintypes` 没有 `ULONG_PTR`，`mouse_event.argtypes` 末位用 `ctypes.c_void_p`。
- 提交：`f57cfa9` feat(shadow)。

### 追加：投影太深、且渗进视频区

用户反馈：阴影颜色太深、发散太重，而且覆盖到了视频区域，只要边框外。

- 渗进视频区的真因：`add_shadow` 把「模糊后的圆角矩形蒙版」整块当阴影层铺下，再
  `alpha_composite` 贴内容——内容不透明的操作栏没事，但视频区是**透明像素**（视频由
  另一个窗口透上来），于是那层黑就压在了视频区上，边缘出现一圈暗角。
- 修法：蒙版算出后减掉内容轮廓 `mask = ImageChops.subtract(mask, hole)`，只在边框外保留
  投影；四角因为本来就在圆角轮廓之外，仍有自然过渡。
- 参数调淡：`SHADOW_BLUR` 4.0 → 3.0、`SHADOW_ALPHA` 120 → 60。
- 实测（白底，内容边缘外扫）：最深只把 255 压到 ~229/236（原来 200），8px 内回到 254；
  内容内像素与阴影无关，视频区不再发暗。
- 测试：新增 `test_no_shadow_inside_content`（内容矩形内 alpha 必须为 0；采样点避开圆角
  轮廓之外的角落，否则那条本来就该有阴影）。全库 74 例通过。

## 第二十一轮：视频区边缘按下不缩放（HWND 类型不一致）+ 贴底放大让位

用户反馈：鼠标放到视频区边缘会变成缩放光标，但按下拖拽没有任何反应。

根因（真 bug）：`user32.WindowFromPoint.restype = wt.HWND`、
`user32.GetForegroundWindow.restype = wt.HWND` 让 ctypes 返回 `c_void_p`，
而 `state['frame']` / `state['child']` 里存的是 int。`c_void_p == int` 永远为 False，
所以 `_owns_point()` 恒 False —— 鼠标压在 scrcpy 子窗口（视频区）上时缩放永远不启动。
同一个 bug 还让 `mirror_visible()` / `force_foreground()` / `toggle_mirror()` 的
`on_top` 判断、以及 watchdog 的前台判断全部恒 False（上一轮「托盘点两次」同源）。

修复：新增 `hwnd_value(h)`（int 原样返回，否则取 `.value`），
`_owns_point` / `mirror_visible` / `force_foreground` / `toggle_mirror` / watchdog
全部改用整数比较。测试新增 `TestHwndValue` 3 例 + `TestOwnsPoint` 2 例。

顺带修：窗口停在屏幕右下角时，左右边缘放大被工作区底边夹住（只长 7px，看起来像
「拖了没反应」）。新增纯函数 `fit_within_bottom(l,t,r,b,bottom_limit,pad)`：左右边缘
放大顶到底边时整体上移让位；上下边缘/四角保持夹取（锚点就是那条边，不能挪）。
`do_resize` 里 `if hit in (10, 11): max_h = max(max_h, wa_h_px - 2*SHADOW_PAD)`。
新增 `TestFitWithinBottom` 4 例。

验收（打包版，窗口 260x610 content / 280x630 window）：
`edgeprobe.py 3409330` → `press at (1635,696)`、`window 280x630 -> 320x718`、
`width delta=40`、`VERDICT OK`；日志 `resize start hit=10` /
`resize end hit=10 from=(1634,396,1894,1006) to=(1584,314,1904,1032)`。

测试 83 例全绿；提交 `9ace24f`；魔芋.exe = 2,769,729 B / 65 文件。

经验：
- ctypes 声明成 `wt.HWND` 的返回值是 `c_void_p`，与 int 比较恒不等 —— 句柄比较统一走
  `hwnd_value()`。
- 外部进程改 Z 序会被前台锁拦住（Edge 最大化盖住时），验证窗口交互必须让程序自己
  置前（`PostMessageW(tray, WM_APP_RAISE)`）。
- `SetWindowPos` 挪窗要用 `SWP_NOACTIVATE|SWP_NOZORDER`（0x0010|0x0004）；
  带 `SWP_NOMOVE`(0x0002) 会让位置不生效。

## 第二十二轮：缩放时吞掉鼠标移动事件，物理光标被冻住

用户反馈：自动注入能拉，自己手动按下拖拽光标完全动不了。

根因：`mouse_hook_proc` 的 resizing 分支对所有消息 `return 1`。低级鼠标钩子返回 1
表示"这条消息我处理了、别往下传"，对 `WM_MOUSEMOVE(0x0200)` 就等于让系统不要移动
光标 —— 物理鼠标冻住，窗口自然也不会变。之前所有探针都用 `SetCursorPos` 逐步摆位置，
而 `SetCursorPos` 不产生输入事件、不过钩子链，所以测试一直是绿的。

修法：新增 `hook_swallow(wparam, resizing)` —— 移动事件永不吞，缩放中只吞按下/抬起；
缩放中的移动照旧 `do_resize()` 并维持缩放光标。补 `TestHookSwallow` 3 例。
新增 `.verify/physprobe.py`：用 `mouse_event(MOUSEEVENTF_MOVE)` 产生真实移动事件
（走钩子）回归 —— 修复前 0/20 移动生效，修复后 19/20 且窗口宽度跟随光标位移。
提交 `a49a6a2`，86 例测试通过。

经验：低级鼠标钩子里**永远不要吞 WM_MOUSEMOVE**；验证输入相关功能必须用
`mouse_event` 注入，`SetCursorPos` 绕过了整条输入链。

## 第二十三轮：摘掉 scrcpy 的任务栏按钮（安卓图标）

用户问："为什么打开魔芋时任务栏会出现安卓图标，点它会单独显示一个纯净的投屏区域"。

答案：scrcpy 是独立进程，它的 SDL 窗口（class `SDL_app`，标题也是「魔芋」）默认带
任务栏按钮和 Alt+Tab 条目；点那个按钮就把光秃秃的视频窗口提到最前。我们的 frame
本来是盖在它上面的，一旦它被激活就露出了裸画面。

修法：新增 `hide_from_taskbar(hwnd)` —— 给子窗口补 `WS_EX_TOOLWINDOW(0x80)`，
再发 `SWP_FRAMECHANGED(0x20)` 让 Shell 重新读样式（任务栏按钮是缓存的不刷新不掉）。
子窗口就位时调用并打日志 `child hide-from-taskbar=True`。

验收：`SDL_app` exstyle `0x08000100 → 0x08000180`；UI Automation 枚举任务栏 26 个
按钮，匹配「魔芋/scrcpy/SDL」的 0 个；截图确认操作栏 + 接缝白线 + 视频画面正常。
89 例测试通过；提交 `d2a0de9`；魔芋.exe = 2,770,772 B / 65 文件。

## 第二十四轮：点窗口外面会"隐藏"、再点原位又冒出来

用户问："点击应用的窗口之外的区域，窗口会隐藏，然后再点击隐藏前的位置窗口又会显示，
帮我检查一下这是不是 bug"。

拆成两半看：

1. "点外面窗口就没了"——不是我们做的。我们刻意不做自动置前（第二十轮用户确认过
   "被遮挡不自动置前"），所以点到的那个程序到前台后就把我们盖住了。这是 Windows
   正常的层级行为。
2. "再点原位置又冒出来"——真 bug。全局低级的鼠标钩子请求置前时只判断"按下的点落在
   frame 矩形内"，没判断那个点上面压着谁；于是窗口被别的程序盖住后，点那个程序的任意
   位置都会把魔芋提到最前。

修法：新增 `should_raise(dy, owns)` —— `owns = _owns_point(pt, f)` 与
`press_should_raise(dy)` 同时成立才 `PostMessage(WM_APP_RAISE)`。被盖住时点别处不再
抢置前；点自己可见区域仍然会置前。补 `TestShouldRaise` 3 例，92 例通过，提交 `9320f9f`。

验收（打包版 2,771,063 B / 65 文件）：被 TXGuiFoundation 窗口盖住时点魔芋原位置 →
日志无 `raise: z bump`、前台仍是对方；把窗口挪到空白处再点自己的视频区 →
`raise: z bump` 出现、前台变回 `CapyMirrorFrame`。

经验：钩子里做"这个点击是不是给我的"判断，只看几何矩形不够，必须叠加
`WindowFromPoint` 归属判断，否则等于给整个屏幕开了个"点哪里都能捞我上来"的洞。


## 第二十五轮（14:4x-14:5x）前台窗口被最小化后自动回前 + 一次严重误触发
