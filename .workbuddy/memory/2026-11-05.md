## 第十九轮：拖动时视频区抖动/右侧底部黑边（根因：我们自己两处尺寸不一致）

- 现象：拖动窗口时视频画面抖动，右/下出现黑边。
- 误判过程：先怀疑 scrcpy 锁定窗口长宽比（dragedge 探针看到 child 尺寸在 264x576 与 260x572 之间跳），于是加了 
  `--no-window-aspect-ratio-lock` 与 `--render-fit=stretched`；加完仍 7/30 步异常。
- 真因：`frame_proc` 的 WM_MOVING(0x0216) 快路径用 `calc_video_rect()` 的**裸尺寸**摆视频窗口，
  而 `position_scrcpy()` 用 `child_box()`（含 OVERSCAN=2）。拖动时两条路径交替执行 →
  视频窗口每帧在 264x576@(-2,36) 与 260x572@(0,38) 之间跳 4px → 画面抖；跳成小尺寸时
  scrcpy 右/下那 1~2px 黑底露进可见区 → 黑边。
- 修法：WM_MOVING 快路径改用 `child_box(...)` 同一套尺寸；新增 `TestDragPath` 守住这条路径。
- 验证（打包版）：`dragedge.py` 30 步 0 异常、offset 恒 (-2,36)、size 恒 (264,576) → VERDICT CLEAN；
  逐边像素：row38 = 纯白接缝线，bottom 605~609 = 201/241/240/239/239 全是画面，无黑边。
- 测试 63 例通过；成品 `D:\moyu\tools\魔芋\魔芋.exe` 2,766,199 B / 65 文件。

## 第十八轮：接缝灰线 + aspect 每秒漂移

- 用户问「灰线下面又有一条白线，正常吗」→ 逐行扫描 30~35=255、36=228（灰）、37=253、38=255、39+ 画面。
- 用 hideframe.py（把 frame 藏起来看 child）确认：灰线是**视频窗口自己最上面 1px 深色描边**（29,29,29）透过半透明操作栏显出来的；白线是我们画的 SEAM_WHITE。
- 修法：白线改画在 `line_y = th - OVERSCAN`（就是那条描边所在行），视频区第一行 `th` 保持透明 → 接缝只剩 1px 纯白。测试 64 例。
- 附带发现大 bug：打包版启动后窗口变横屏 572x270 并弹「无线调试未开启」框。日志 aspect updated 2.2331 → 2.2119 → … 2.0000，每秒 -0.0212。
- 根因：watchdog 每秒量 child 尺寸（含 overscan 264x576）+ adopt_aspect 用绝对阈值 0.02 → 每秒 ~1% 的变化刚好被采纳 → 量到→改窗口→再量到 的正反馈。
- 修法：adopt_aspect 同方向只接受 >20% 相对变化、竖↔横直接采纳；两处测量先减 2*OVERSCAN。测试 65 例通过，打包部署 2,766,536 B / 65 文件；提交 99542af。
- 环境：`adb devices` 为空 —— 手机无线调试已断开，scrcpy 连不上，需用户重新开启（端口变了要给新配对码）。
- 离线验收脚本 `.verify/seamproof.py`：用 build_frame_image 叠模拟画面，结果 y=36 alpha=255 纯白（合成 255）、y=37 alpha=224、y=38 alpha=0 露出画面 → 接缝就一条 1px 白线。

## 第十九轮：整窗阴影

用户需求：给整个窗口（操作栏+视频区域）加淡淡阴影；随时可回退。

- 难点：窗口是 UpdateLayeredWindow 分层窗口，系统不会给它画阴影（没有非客户区）。
- 方案：窗口四周外扩 `SHADOW_PAD=10`，在这圈里自己画模糊的黑色圆角矩形；圈内对鼠标返回
  `HTTRANSPARENT`(-1)，避免吃掉桌面点击。否决「再开一个阴影窗口」——多一个要同步的窗口，
  会重演之前的脱节/闪烁问题。
- 常量：`SHADOW_PAD=10`、`SHADOW_BLUR=4.0`、`SHADOW_ALPHA=120`；回退只需 `SHADOW_PAD=0`。
- 新增纯函数：`content_size` / `content_rect` / `win_rect` / `add_shadow`，坐标换算全部走它们，
  不再散落硬编码。
- 接线：`update_frame`（画布外扩 + `add_shadow`）、`position_scrcpy`、`WM_MOVING`、
  `frame_hittest`（操作栏/关闭按钮/抓边都 +pad，圈带返回 HTTRANSPARENT）、`_inside_frame`
  （用内容矩形，`edge_hit` 的 toolbar 传 `TOOLBAR_H+SHADOW_PAD`）、`start_resize`（存内容矩形）、
  `do_resize`（`win_rect` 落地，`max_w/max_h` 减 pad）、`WM_GETMINMAXINFO`、`ensure_frame_orientation`、
  `main()` 建窗尺寸。
- 测试：`TestShadowPad` 3 例 + `TestAddShadow` 5 例，全库 73 例通过。
- 实测：280x630 窗口（内容 260x610）；白底上阴影把 255 压到 200，8~10px 内衰减到 255；
  视频子窗口偏移恒 `(8,46)=(PAD-OVERSCAN, PAD+TOOLBAR_H-OVERSCAN)`；拖左边缘 −40px →
  窗口 320x718、内容同步、子窗口偏移不变（`VERDICT OK`）。
- 坑：注入式测试前必须重新 `GetWindowRect`，用户同时在动窗口会让注入点打空（第一轮误判「没缩放」）；
  `ctypes.wintypes` 没有 `ULONG_PTR`，`mouse_event.argtypes` 末位用 `ctypes.c_void_p`。
- 提交：`f57cfa9` feat(shadow)。
